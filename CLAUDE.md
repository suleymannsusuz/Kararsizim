## Architecture notes that span files
- **Custom user model** (`accounts.User`, `AUTH_USER_MODEL`) logs in by **email** (`USERNAME_FIELD = "email"`). `UserManager` and `User.save()` both lowercase email and username, and case-insensitive `UniqueConstraint(Lower(...))` backs it at the DB level. `first_name`/`last_name` are removed, so the admin in `accounts/admin.py` defines its own fieldsets; keep them in sync with the model. Never change the user model after migrations are applied elsewhere.
- **Auth flow** (`accounts/`): `RegisterForm` is a plain `forms.Form` (not a ModelForm) so duplicate checks are explicit `__iexact` queries with Turkish messages, and it validates username (`^[a-z0-9_.]{3,20}$` after lowercasing, plus the reserved-names set) and passwords. `LoginForm` takes an email in the `username` field and lowercases it, because lookup is an exact match against the stored lowercase email. Logout is Django's POST-only `LogoutView`. Shared form markup is `templates/partials/form_fields.html`.
- **Settings** (`config/settings.py`) read everything from env vars. `DATABASE_URL` empty/unset falls back to SQLite (`dj_database_url.parse` with an explicit `or`, because `dj_database_url.config` does not fall back when the variable is set but empty). When the URL is Postgres, `DISABLE_SERVER_SIDE_CURSORS=True`, `sslmode=require` (opt out with `DATABASE_SSL_REQUIRE=False`) and `CONN_MAX_AGE=0` are applied for the Supabase transaction pooler. `manage.py test` ignores `DATABASE_URL` and always uses SQLite, so tests never touch the remote database. `env_bool` treats an unset or empty variable as "use the default". On Vercel (`VERCEL=1`) the allowed hosts and CSRF origins come from `VERCEL_PROJECT_PRODUCTION_URL`/`VERCEL_URL`/`VERCEL_BRANCH_URL` and the production security block (SSL redirect, secure cookies, 1-year HSTS, `X-Forwarded-Proto`) turns on automatically; elsewhere set `DJANGO_SECURE=True`; with `DEBUG=True` it never turns on, and local `DEBUG=False` runs stay plain-http friendly. `config/tests.py` loads the settings in a clean subprocess to assert all of this. Static files: no whitenoise, because Vercel runs `collectstatic` itself when `STATIC_ROOT` is set and serves them from the CDN (only `vercel.json` with `regions: ["fra1"]` and `.python-version` were added for deploy).
- **Supabase is only a Postgres host.** No Supabase Auth, anon key or JS client; all data access goes through Django. Migrations run locally against the remote DB, never in the Vercel build.
- **Voting identity** (`polls/voting.py`): `voter_key` is `u:<user id>` for members and `a:<uuid>` from a signed `kz_voter` cookie for guests; `UniqueConstraint(poll, voter_key)` plus `IntegrityError` handling in `cast_vote` enforces one vote. The guest cookie is written only after a successful vote (`current_voter_key` reads without creating one; `identify_voter` may mint a new id). Results are hidden from non-owners until they vote, and votes cannot be changed.
- **Results rendering**: always load polls through `Poll.objects.with_results()` (prefetches options annotated with `vote_count`) and pass them to `attach_results(polls, voter_key, viewer)`, which adds `results`, `total_votes`, `show_results`, `is_owner` etc. in one extra query for the viewer's votes. Vote buttons are driven by `poll.can_vote` (not voted and not closed), independent of `show_results`: the owner sees results and buttons together until they vote (`main.js` then updates the existing `.legend` instead of adding a second one). Templates must only render per-option counts when `poll.show_results`; `tests.py` asserts the feed query count stays constant as polls grow. `partials/poll_card.html` is shared by feed, profile and detail (`detail=True` adds the owner's delete button). The card shows a segmented distribution bar (`.dist` > `.dist-fill` > `.seg` with `flex-grow` = votes; empty grey track until the viewer may see results), a verdict line from `status_label()` in `polls/voting.py` ("Karar net", "Az farkla önde", "Kafa kafaya", "Kalabalık da kararsız", or "İlk oyu sen ver"/"Henüz oy yok" when there are no votes), and a `.legend` list. Verdicts that hint at the distribution are only produced when `show_results`, so they must never be rendered for viewers who have not voted. Feed and profile pages set `{% block body_class %}is-wide{% endblock %}` for the two-column `.poll-grid`; detail, create and auth pages stay narrow.
- **Vote endpoint contract** (`polls/views.py`): `POST /anket/<id>/oy/` returns JSON only when the request has `Accept: application/json` (200 saved, 409 duplicate with the same results payload, 400 invalid option; results include `position` for the color class, and `status_label` feeds the verdict line), otherwise redirects with `messages`. `static/js/main.js` is a no-build, no-framework enhancement layer that builds the result DOM with `textContent` (never `innerHTML`, since option text is user input) and mirrors the markup of `partials/poll_card.html`; change both together. It also handles the confirm-on-submit hook (`data-confirm`), the `0/140` counter (`data-counter`), and add/remove option rows (`data-poll-form`, `data-option-row`).
- **Closing polls**: `Poll.closed_at` (null = open; `is_closed` is a read-only property, so never assign to it) is set once by the owner via `POST /anket/<id>/kapat/` (owner-only 403, idempotent). `cast_vote` returns `VoteResult.CLOSED` first, so closed polls never accept votes (HTML: message; JSON: 409 with the results payload plus `closed: true`). A closed poll's results and verdict are public to everyone, because no vote can be influenced any more; open polls keep results hidden until the viewer votes. Migration `0002_poll_closed_at` has been applied to local SQLite only; it still has to be run against Supabase (`migrate` with the real `DATABASE_URL`), and no new table is created so the RLS step is not needed again.
- **Feed and profile**: `?sirala=populer` orders by vote count (annotated as `vote_total`, not `total_votes`, which `attach_results` sets per poll); `?sirala=kapananlar` lists closed polls by `closed_at` descending (closed polls also appear, tagged "Kapalı", in Yeni and Popüler); unknown values fall back to newest. Pagination links carry the sort through the `extra_qs` context variable. `/u/<username>/` looks the user up lowercased and shows only that user's polls. Avatar colors come from the `avatar_color` filter in `polls/templatetags/poll_extras.py` (deterministic, not Python's randomized `hash()`).
- **Poll creation form** (`polls/forms.py`): options are repeated `options` inputs read with `getlist` (not fixed fields), so a 6th option is rejected instead of silently dropped; Faz 3's add/remove JS must keep that field name. Option colors come from `position` via `.opt-0`…`.opt-4` classes setting `--c`.
- **Error pages** (`templates/404.html`, `403.html`, `500.html`): 404 and 403 extend `base.html` through `partials/error_card.html` (Django passes the request, so the navbar works) and deliberately never echo the requested path. **`500.html` is standalone**: Django renders it with no request or context, so it must not use `base.html`, `user`, `{% url %}` or `{% csrf_token %}`; it links `css/main.css` through plain `{% static %}`, so the production static setup (whitenoise, Faz 4) has to serve that file or the 500 page renders unstyled. `ErrorPageTests` triggers a real 500 with a test urlconf.
- **Email must never be exposed** in templates, JSON responses or page source; authors are shown by `username` only.
- **JS is progressive enhancement only**: every flow (vote, create, delete, logout) must work as a plain form POST + redirect with JS disabled. State-changing actions are POST-only.
- Templates are in the top-level `templates/` (`base.html`, `partials/`), statics in `static/`. The navbar currently hard-codes `/giris/`, `/kayit/`, `/cikis/`, `/u/<username>/`, `/anket/olustur/` paths, which will be real routes in later phases; keep URL paths in Turkish as specified in the plan.
- UI text is Turkish, identifiers and code are English. Admin lives at `/yonetim/`, not `/admin/`.
